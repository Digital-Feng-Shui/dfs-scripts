# Performance + SEO audit, 24 Oct 2026

Two staging pages, judged as if they go live next: the new homepage (will replace `/`) and Meet Tinko (the landing for Tinko ads, leads into Fundamentals). Read and measured only, nothing changed.

**How it was measured.** Lighthouse 12.6 in headless Chrome, mobile (simulated slow 4G, 4× slower CPU) and desktop, each run 2–3 times. Then a real Chrome run per page (desktop 1440×900, and mobile 390×844 at 4× slower CPU + 1.6 Mbps): load, 5 s idle at the top, a slow wheel scroll to the end, 5 s idle at the bottom, while counting every `requestAnimationFrame` loop by the function that schedules it, main-thread time, layouts, long tasks, layout shifts and all bytes. Versions: dive-v0.9.35, meet-tinko-v0.3.34, main.js/styles.css v1.7.95.

"Idle CPU" below = how busy the main thread is while nobody touches the page. 0–5 % is normal. Above 50 % on a phone means a warm phone and a drained battery.

## 1. New homepage (`/rimbo-home-test`)

### Numbers

| | Mobile (Lighthouse) | Desktop (Lighthouse) |
|---|---|---|
| Performance score | 46–60 | 88–89 (one slow-network run: 56) |
| LCP (biggest text on screen) | **8.3–8.8 s** (good < 2.5 s) | 1.4–1.6 s |
| FCP (first paint) | 4.3–4.7 s | 1.1–1.3 s |
| TBT (blocked main thread) | 150–590 ms | 0–30 ms |
| CLS (layout shift) | 0–0.003 | 0.057 (`h1.dive_title` words) |
| First load | 35 requests, 973 KB | same |
| After a full scroll | 98 requests, 1.6 MB (no video plays unless clicked) | same |

Real Chrome run:

| | Desktop | Mobile (4× CPU) |
|---|---|---|
| Idle CPU at the top | 18 % | **69 %** |
| Idle CPU at the bottom (footer) | 20 % | **78 %** |
| Frames while scrolling | smooth (p95 9 ms), one 0.5 s hitch | p95 42 ms (≈ 24 fps), 55 frames over 50 ms |
| Long tasks | 5, worst 717 ms at start | 36, 2.6 s in total |
| Layouts per second while idle | ≈ 130 | ≈ 140 |
| JS memory | 23 MB | 17 MB |

Why LCP is 8 s on mobile: the text is ready at ~0.6 s, but it stays invisible (`html:not(.dive-ready) [data-dive-title], [data-dive-end] {opacity:0}` in the page head) until `dive.js`, the Paper shader module and the arrival sequence have run. Lighthouse puts 7.8 s of the 8.3 s in "render delay".

Why idle CPU is high: eight animation loops run every frame, everywhere on the page, also when their section is far off screen. Three of them have no visibility check at all and read element positions every frame (`getBoundingClientRect`), which forces a fresh layout of the 23,000 px page about 130 times a second.

### Top 5 fixes

| # | Fix | Effort | Gain | Chat |
|---|---|---|---|---|
| 1 | **Show the hero line in the first paint.** Drop the `opacity:0` until `dive-ready` for `[data-dive-title]` (and keep the word-rise as a CSS animation that starts at once), so the H1 doesn't wait for the module + shader + arrival. The swirl can still develop behind it. | S | Mobile LCP ≈ 8.3 s → ≈ 3–4 s (about the FCP). Biggest single score gain. | HOME PAGE |
| 2 | **Stop the always-on loops in `dive.js`.** `tickLogo` (line 141–152) rewrites the star's two mask paths every frame even between ticks (it only moves 0.8 s of every 4.4 s), and keeps scheduling itself after the logo has faded out; `bgFrame` (757–799) and `handover` (1182–1196) read 3 element rects every frame on the whole page. Start/stop them with an IntersectionObserver (as `initStand`/`initMission` already do) and only write when a value changes. Also stop rescheduling the guarded loops (`frame` at 896, 1034, 1124) while their section is hidden. | S–M | Idle CPU 18–78 % → near 0. Cooler phones, smoother mobile scroll (p95 42 ms now). | HOME PAGE |
| 3 | **Render the dither shaders at a sane size.** Paper's `ShaderMount` defaults to `minPixelRatio = 2` and `maxPixelCount = 8.3 MP`, so on a 1440×900 screen the hero, the time-story background and the close each draw a **3643×2277** canvas (4 of them on the page). Pass `minPixelRatio 1` and e.g. `maxPixelCount 1920*1080` (args 7 and 8 of `new ShaderMount(...)` in `dive.js` line 121 and 726, and `dither()` in `solutions.js` line 879). The look is pixel art with 2 px+ dots, so nothing visible is lost. | XS | ≈ 4× less GPU work per frame on desktop and laptops (less fan, less battery). | HOME PAGE |
| 4 | **Split up the start-up work.** One 576–717 ms task at load, mostly `dive.js`: building the time-story year (365 days), the mission globe and the stand cards, then the first `progress()` → `getBoundingClientRect` (line 189) forces a full layout of the whole page. Build the sections below the fold when they come near (as `solutions.js` already is) and read layout once. | M | TBT 150–590 ms → < 100 ms on mobile, faster first taps (INP). | HOME PAGE |
| 5 | **SEO basics before it becomes `/`.** Title is "rimbo home test", no meta description, OG/Twitter title "rimbo home test", no OG description or image (live `/` has all of these in its page settings: copy them over). The canonical points at `/rimbo-home-test`; fine once it is the Home page. The links to Fundamentals ("See the course", "Start the course", footer and bottom nav) all go to `/`, which will be this page itself after the swap: point them at the Fundamentals sales page's new URL. | XS | Correct Google result and share card; no self-links. | HOME PAGE |

### Also seen (smaller)

- `dive.js` (28 KB) and `solutions.js` (35 KB) are served unminified; jsDelivr serves a minified copy if the tag asks for `dive.min.js` (unminified saves ~18 KB per Lighthouse).
- Bottom nav "Meet Tinko" and "Resources" link to `#` (should be `/meet-tinko`, `/resources`); footer "About", "Updates & Insights", "Newsletter" and one social icon are `#`; all three journal cards go to `/blog`, not to their posts (known: needs the Designer).
- Footer column titles (Product, Company, Resources) are H3s; make them plain text. The rest of the heading order is fine: one H1, then H2/H3.
- No structured data. Add `Organization` + `WebSite` JSON-LD on the homepage.
- Accessibility flags that also cost SEO points: `aria-label` on plain `<p>` (`.dive_end`, `.time_note`, mission notes) is ignored by screen readers (use a visually hidden span); contrast too low on `.stand_tag` and `.stand_card-text`; about half the text on mobile is under 12 px.
- The rAF loops above also run inside `solutions.js` demos, but those already pause off screen. Good.
- Crawlers that skip JS still get ~775 words of real text and all headings in the HTML. Good.

### Top 5 fixes

| # | Fix | Effort | Gain | Chat |
|---|---|---|---|---|
| 1 | **Use the 8 s clips in the course section.** `tinko.js` (line 1981–1988, `st.load`) sets `preload='auto'` on Bunny's full `play_360p.mp4` (a 190 s lesson) and loops 8 s from `#t=`. The browser buffers ~100 s anyway: 3.4 MB on desktop, and on mobile the same file was fetched twice, **11.5 MB**. Swap in the clips in `DFS/meet-tinko-clips`, and keep `preload='none'` until the section is near. | S (clips exist) | −3 to −11 MB per visit. For ad traffic on mobile data this is the biggest win on the page. | TINKO LANDING PAGE |
| 2 | **Show the hero text in the first paint.** The page head hides `[data-tinko-title]` and `[data-tinko-intro]` until `tinko.js` adds `tinko-ready`, after Tinko's intro (pixels in, wake, glide); the fallback timer is 12 s. Lighthouse: 8.5–9.3 s of the 9–9.8 s mobile LCP is this wait. Let the title and sub line be visible (or rise via CSS at once) and play Tinko's intro beside them; drop the fallback to 2–3 s. | S | Mobile LCP ≈ 9 s → ≈ 3–4 s. Ads platforms and visitors both reward a fast first screen. | TINKO LANDING PAGE |
| 3 | **Load the cube's far face later, or lighter.** The cube preloads the full `/` page in a hidden iframe as soon as the outro is 1.5 screens away (`tinko.js` line 1594–1597). That frame runs the whole site again: Memberstack (147 KB), GA, Meta Pixel and Clarity (page views counted twice), its own animations (350 ms long tasks on mobile, idle CPU 65–98 %). Preload on intent only (hover/Space, or progress > 0.9), or use a static snapshot image for the cube face; if it stays an iframe, give it a flag (e.g. `?embed`) that skips the trackers. | M | Correct ad/analytics numbers, ~1 MB and a lot of CPU less near the end. | TINKO LANDING PAGE (WEBSITE if main.js needs the embed flag) |
| 4 | **Stop the hero from pushing the page down.** `section#mess` ("Years Of Clutter.") jumps once Tinko's box opens in the hero: CLS 0.22 desktop, 0.37 mobile. Google counts CLS for ranking and ad quality. | TINKO LANDING PAGE |
| 5 | **Launch checklist for SEO and social.** (a) The page head has `<meta name="robots" content="noindex">`: remove it at launch. (b) No OG/Twitter tags at all: add OG title, description and a share image (ads and shared links show an empty card now; the page has no images in its HTML for a fallback, all 38 are drawn by JS). Once the new homepage is `/`, that leads to the homepage dive instead of Fundamentals: point both at the Fundamentals sales page's URL. (d) The HTML contains the Designer note "Placeholder, not on the site: meet/tinko.js draws…" (hidden by CSS, but link previews and non-JS crawlers read it); move it to a custom attribute or Designer-only comment. | XS | Indexable page, proper ad/share previews, the funnel lands on the right page. | TINKO LANDING PAGE |

### Also seen (smaller)

- Tinko's hero morph rewrites his SVG path every frame while he is on screen (`frame`, `tinko.js` line 159–182): 23–29 % idle CPU on desktop, 80 % on a slow phone. Capping the morph to 30 fps, or pausing it after a few idle seconds, roughly halves that.
- `injectCSS()` (`tinko.js` line 2282) adds Google Fonts Space Mono at run time: one more origin and a late font swap. Self-host it, or use RM Mono, which the site already loads.
- `tinko.js` (63 KB) is served unminified; `tinko.min.js` via jsDelivr is free.
- Headings are clean: one H1 "Meet Tinko.", then H2/H3 in order. Text for crawlers: ~840 words in the HTML. Good.
- No structured data. A `SoftwareApplication` (Tinko, macOS) or an `Offer` tied to the Fundamentals `Course` would fit.
- Contrast too low on `.hero_tag-text.is-small`; some demo text is 10–11 px (fine as decoration, it is aria-hidden).

## 3. Site-wide (WEBSITE)

These hit both pages (and every other page). Ranked by impact:

1. **The Webflow Optimize/Analyze script** (`/g0lnomhfn…`, the `data-wf-intellimize-customer-id` on `<html>`) is the biggest script on both pages: 168 KB, ~120 ms main thread. If Optimize/Analyze is not in use, switch it off in Site settings. Gain: −168 KB on every page. Effort XS.
2. **Two sync scripts in `<head>`**: `vmj7qw1x3g-1.1.1.js` and `dfs_loader-1.0.0.js` (Webflow-registered scripts). Tiny, but each blocks the first paint for a full round trip (Lighthouse: ~0.8 s each on mobile). Load them `async`/`defer`. Effort XS.
3. **Trackers**: gtag 163 KB (119 KB unused), Meta Pixel 112 KB, Clarity 25 KB, Cloudflare Turnstile 28 KB (loaded at start; it is only needed once someone opens a form). Load gtag and Clarity after the first interaction or on idle; keep the Pixel early only where ads land (Meet Tinko). Effort S.
4. **jsDelivr in the head**: `styles.min.css`, `night.min.css` and `night-early.min.js` come from a second origin with no `preconnect`. Add `<link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin>`. `main.min.js` is 56 KB with 41 KB unused on these two pages. Effort XS.
5. **Live site hygiene**: `www.digital-fengshui.com/rimbo-home-test` is published on live, indexable (no noindex) and listed in `sitemap.xml`: a duplicate of the future homepage. Exclude it from the sitemap and noindex it now; 301 it to `/` after the swap. The Memberstack toast in the nav component ships the placeholder text "This is a success message. This is auccedmessage." on every page (crawlers read it). `/rythems-app` (typo slug) is live and in the sitemap; renaming it needs a 301.

Smaller: Lenis runs its own rAF loop next to GSAP's ticker (drive Lenis from `gsap.ticker` for one loop); `dfs-site.thomas-aukema.workers.dev/site.js` is cached for only 60 s (Thomas).

Staging itself is `Disallow: /` in robots.txt on purpose. That is why Lighthouse SEO shows 61/69. Without it, the homepage would mainly lose points for the missing description, and Meet Tinko for its noindex meta.
